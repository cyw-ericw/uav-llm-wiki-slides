Wiki 與流程反思

建立 Wiki 時，證據要細到能回答新生的下一個問題。 例如 S02 同時談標準版和新版。若只抄下第一組型號，寫簡報時很容易把它教成所有 6C 的規格。這次先在來源卡記錄版本，再讓教學頁只說「先辨認版本」。同樣地，第 09 頁把 Loiter 需要的有效定位、非 GPS 例子的原點條件、光流在範例裡提供的水平速度分別連回 S03、S06、S08。讀者可以找出每一項限制出自哪裡。逐頁對照

最常出現的內容問題是證據指得不夠精確。 以獨立內容審查退回的正文主張計數，5 個都出在 Evidence，分布於 3 頁。最清楚的例子是第 06 頁。結構檢查已找到 S03，仍無法回答「這一條摘要究竟有沒有寫出飛手負責高度」。精確補上 S04.1 後，能從投影片一路讀回原卡和原文。若以失敗的完整測試輪數計算，大綱驗證、忠實度、瀏覽器矩陣各有一輪失敗；30 個瀏覽器斷言來自一個測試器原因，不能當作 30 個獨立的版面錯誤。

把歸因放在修改前面，可縮小退回範圍。 原流程容許忠實度退回逐頁稿或證據卡；這次在 workflow 明列「句子正確、條目太籠統 → Evidence」。接著在渲染前綁定已核准的資料指紋；HTML 只負責呈現。第二輪五個退修點全數通過，其他逐頁稿與 Wiki 雜湊一致。瀏覽器層則先用實際按鍵重現，故只調整測試事件的目標。這批重測沒有再出現同一問題，尚無後續批次可據以推論長期成效。

停止條件。 本次各局部問題均在一次修正後完成重驗，沒有走到三輪上限。已使用的技術主張沒有待補來源。未來若某項主張找不到原頁段落、條件衝突未解，或三輪後仍無法通過，該頁應停在來源或忠實度節點並登記待確認。使用者對投影可讀性及正式發布的決定另列待辦。

人工驗收回饋：換頁導覽列位移（2026-11-21）

使用者於 Mac Chrome 本機開啟 deck.html 後，回報連續點擊「上一頁／下一頁」時，按鈕會隨不同頁面內容高度和展開的自我檢核／本頁證據區塊位移，妨礙連續操作。這是正式使用者驗收新發現的 UI 問題，與前述原始簡報瀏覽器測試分開記錄。

  • 問題節點：Render → HTML UI/UX；原因是 .nav 留在正文正常文件流的底部，位置取決於當前 slide 高度。
  • 退回與局部修正：只修改 scripts/deck-template.html 的 CSS，使 .nav 固定於視窗底部，依側欄與螢幕寬度調整左右邊距；在 .stage 底部加入安全留白，避免固定導覽列遮蔽最後一行；不改任何 Draft、Evidence Card、Wiki、JavaScript 及主題配色。
  • 重新執行：由 scripts/render.py 重新產生 slides/deck.html，scripts/check_render.py PASS（11 頁、34 個正文主張、11 組問答及來源連結一致），scripts/check_slides.py --draft PASS。
  • 獨立瀏覽器驗證：在 headless Chromium（Playwright）以 1440×900、1024×768、768×1024、390×844、320×568 五種 viewport，各實測 10 次下一頁與 10 次上一頁（合計 100 次）。所有尺寸的 prev、next 按鈕螢幕座標在 11 頁和詳細資料展開前後均不變（容差 0.5 px）；無水平溢出；頁面 1、11 的停用邊界及右方向鍵導航通過。原始結果見 checks/navigation-ux-fix.json。
  • 尚未驗收：此修正版尚需使用者以 Mac Chrome／Safari 實機重新操作確認手感；不可把 headless Chromium 測試視為 Safari 或投影機驗證。

反思與剩餘驗收

最多失敗集中在 HTML 版面關卡。雖然底部導覽使用固定定位，展開較長內容時，捲軸仍會改變可用寬度；V2 與 V3 之間的文字盒尺寸也須一致。跨版型連點、同時量測兩個按鈕的四個幾何量，才能捕捉這個問題。第 06 頁也顯示整頁寬度正常時，單一表格儲存格仍可能裁字，因此另保留逐格檢查。

  • 待使用者檢視三種版型的可讀性、圖解層次與換頁手感，再決定其餘八頁。
  • 待 macOS Safari／Chrome 以 Finder 直接開啟下載的 HTML、macOS 系統「減少動態效果」、實體手機觸控與投影距離下的字級驗收。獨立 headless Chromium 在原執行環境啟動受限，其後以實際受管 Chromium 完成上述測試。該瀏覽器允許 HTTP 預覽，限制直接載入 file URL。
  • 外部官方連結需連網閱讀。離線時可閱讀簡報正文、問答、逐條引用名稱與圖解。

反思與待人工驗收

本輪只有圖解忠實度節點出現一次失敗。同一張圖同時畫出機身高度與水平位置，很容易在短圖說裡將兩條控制軸的條件寫在一起。檢查時將「哪支桿回中」與「哪個量被保持」逐句配對，才發現第 09 頁的歧義。幾何或連結檢查無法代替這項判讀。

瀏覽器重測未觀察到水平溢出或導覽偏移。手機卡片用較多垂直空間換取完整欄名；定位條件、自我檢核及證據可繼續向下捲動閱讀。實體手機觸控、投影機亮度與後排字級、Mac Safari／Chrome 從 Finder 直接開啟 HTML，以及 macOS 系統減少動態效果仍待人工驗收。離線閱讀簡報可使用所有內嵌圖解與互動，前往官方原文需網路。正式部署須另行授權。
